# astrid-capsule-identity

[![License](https://img.shields.io/badge/license-MIT%20OR%20Apache--2.0-blue.svg)](LICENSE-MIT)
[![Node](https://img.shields.io/badge/node-%3E%3D20-green.svg)](package.json)

**The identity and system prompt builder for [Astrid OS](https://github.com/unicity-astrid/astrid).**

In the OS model, this capsule is `/etc/profile` — it owns who the agent is and
what it says about itself before anything else runs.

This is the JavaScript port of the original Rust capsule. It is a behavioural
re-implementation: the same hook actions, the same IPC topics, the same JSON and
TOML bytes on the wire, and the same log lines. See `truth.md` for the migration
record and the registered divergences.

## How it works

On `spark.v1.request.build`:

1. Builds an `# Environment` block from the request's `workspace_root`.
2. If the agent has not onboarded yet, it tries to auto-detect an identity from
   `home://.config/spark.toml`, so the capsule survives a KV reset.
3. If an identity is known, its preamble is prepended to the prompt.
4. Otherwise an onboarding instruction is appended, telling the agent to walk the
   user through identity setup and then call `save_identity`.

The resulting prompt is published on `spark.v1.response.ready`.

## IPC protocol

| Direction | Topic | Purpose |
| --- | --- | --- |
| Subscribe | `spark.v1.request.build` | Build the system prompt |
| Subscribe | `tool.v1.execute.save_identity` | Persist the identity chosen during onboarding |
| Subscribe | `tool.v1.request.describe` | Advertise the `save_identity` tool |
| Subscribe | `cli.v1.command.execute` | `identity-export` / `identity-import` |
| Publish | `spark.v1.response.ready` | The built system prompt |
| Publish | `tool.v1.execute.*.result` | Tool execution result |
| Publish | `tool.v1.response.describe.*` | Tool descriptor |
| Publish | `agent.v1.response` | CLI command output |

## Layout

| Path | Purpose |
| --- | --- |
| `src/identity.js` | The capsule logic — direct transcription of the Rust `src/lib.rs` |
| `src/capsule.js` | The hook dispatch table generated by Rust's `#[capsule(state)]` macro |
| `src/schema.js` | The `save_identity` tool descriptor |
| `src/sdk/` | The parts of `astrid-sdk` this capsule uses, over an injectable host |
| `src/rust/` | Emulation of Rust library semantics (`serde_json`, `toml`, `str`) |
| `harness/` | Differential harness and fixture corpus |

## Development

```sh
npm test          # unit tests ported one-for-one from the Rust #[cfg(test)] module
npm run build     # syntax check + manifest validation
npm run lint      # style and hygiene checks
npm run differential   # replay every fixture against the Rust oracle
```

`npm run differential` needs the Rust capsule compiled to WebAssembly. Point
`ASTRID_ORACLE_WASM` at the built artifact:

```sh
cargo build --release --target wasm32-unknown-unknown   # in the Rust repo
ASTRID_ORACLE_WASM=/path/to/astrid_capsule_identity.wasm npm run differential
```

## Running it

```sh
echo '{"workspace_root":"/tmp/ws"}' | node bin/capsule.js hook handle_build_request
```
